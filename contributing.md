# Contribuir a KimiXP

Gracias por tu interés en contribuir a **KimiXP**.

KimiXP es un proyecto Open Source y cualquier persona puede revisar el código, proponer mejoras, reportar errores o contribuir directamente al desarrollo.

No necesitas ser un desarrollador experto para aportar. Incluso una buena documentación o un reporte de error bien explicado puede ser útil.

---

## 📋 Antes de empezar

Antes de contribuir, te recomendamos:

* Leer el `README.md`.
* Revisar los Issues existentes.
* Revisar las Pull Requests abiertas.
* Comprobar que tu cambio no haya sido propuesto anteriormente.
* Entender las partes del proyecto que vas a modificar.

Si estás empezando con Python, puedes utilizar KimiXP como una oportunidad para aprender.

---

## 🐛 Reportar errores

Si encuentras un error, puedes abrir un Issue.

Procura incluir:

* Qué estabas haciendo.
* Qué esperabas que ocurriera.
* Qué ocurrió realmente.
* El mensaje de error, si existe.
* La versión de KimiXP que estás utilizando.
* Información relevante sobre tu entorno.

No publiques nunca:

* Tokens de Discord.
* Contraseñas.
* Claves API.
* Archivos `.env`.
* Información privada de usuarios.

---

## 💡 Proponer funciones

Si tienes una idea para KimiXP, puedes abrir un Issue explicando:

* Qué función propones.
* Para qué serviría.
* Cómo podría funcionar.
* Por qué crees que sería útil.

Las propuestas serán revisadas antes de incorporarse al proyecto.

No todas las propuestas tienen que ser aceptadas, pero todas pueden servir para discutir nuevas posibilidades para KimiXP.

---

## 🔧 Contribuir con código

Si quieres modificar el código, puedes trabajar mediante un **fork** del repositorio.

### 1. Haz un fork

Crea una copia del repositorio en tu propia cuenta de GitHub.

### 2. Clona tu fork

```bash
git clone https://github.com/TU-USUARIO/KimiXP.git
cd KimiXP
```

### 3. Crea una rama

Evita trabajar directamente sobre `main`.

```bash
git checkout -b feature/nueva-funcion
```

Para una corrección:

```bash
git checkout -b fix/correccion-error
```

### 4. Realiza tus cambios

Modifica únicamente lo necesario y procura mantener la estructura existente del proyecto.

Antes de enviar tus cambios, revisa que:

* El código sea entendible.
* No hayas incluido información sensible.
* No hayas eliminado funcionalidades existentes accidentalmente.
* Las nuevas funciones funcionen correctamente.

### 5. Haz commit

Utiliza mensajes claros:

```bash
git add .
git commit -m "Add sistema de perfiles"
```

Evita mensajes demasiado genéricos como:

```text
update
changes
final
asdf
```

### 6. Envía tus cambios

Sube tu rama:

```bash
git push origin feature/nueva-funcion
```

Después puedes abrir una **Pull Request** desde GitHub.

# 🔀 Pull Requests

Antes de abrir una Pull Request:

* Comprueba que el código funciona.
* Revisa tus propios cambios.
* Explica qué modificaste.
* Explica por qué realizaste el cambio.
* Indica si existe algún problema conocido.

Una Pull Request puede ser revisada, modificada o rechazada.

Esto no significa que el código sea malo. Algunas modificaciones simplemente pueden no encajar con los objetivos actuales de KimiXP.

---

## 🧹 Estilo del código

Procura mantener el código sencillo y consistente con el resto del proyecto.

Como KimiXP está desarrollado en Python:

* Utiliza nombres descriptivos.
* Evita código innecesariamente complejo.
* Mantén las funciones organizadas.
* Añade comentarios cuando realmente ayuden a entender el código.
* Evita duplicar código cuando sea posible.
* No introduzcas dependencias innecesarias.

No es necesario que tu código sea perfecto, pero sí debe ser razonablemente claro y mantenible.

---

## 🔐 Seguridad

Si encuentras una vulnerabilidad de seguridad que pueda afectar a KimiXP o a sus usuarios, **no publiques los detalles públicamente en un Issue**.

Utiliza el canal de contacto de seguridad indicado en el repositorio para informar del problema de forma responsable.

Nunca publiques credenciales, tokens o información privada.
